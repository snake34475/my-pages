原码、反码、补码、移码
四兄弟的爱恨情仇

为什么 0 会有两个？为什么 -128 比 -127 还多一位？为什么计算机里减法根本不存在？—— 8 位小剧场，开演。

先纠正一个千古乌龙：是「原码」不是「源码」。源码是程序员写的，原码是机器想的。 你要是跟考官说"源码"，他会给你现场演示什么叫"反码"——把你的分数按位取反。

01先认人：四个码都是什么脾气

下面全部以 n 位定点整数为例，最高位是符号位：0 正 1 负。

Sign-Magnitude

原码 最老实，也最坑

符号位 + 真值的绝对值。人看着最舒服，机器用着最难受。

+9 → 00001001    -9 → 10001001
🎭 双胞胎事件：+0 = 00000000，-0 = 10000000。判零电路当场裂开：两个长得不一样的数，你说它们相等？
One's Complement

反码 原码的镜像世界

正数 = 原码；负数 = 符号位不动，其余按位取反。

-9 → 11110110  （0001001 取反得 1110110）
🪞 还是俩 0：-0 = 11111111。而且加法做完可能要"循环进位"，硬件工程师表示不想加班。
Two's Complement

补码 终极赢家，一统江湖

正数 = 原码；负数 = 反码 + 1 = 「模 2ⁿ 减去 |x|」。符号位直接参与运算，减法变加法。

-9 → 11110111  （11110110 + 1）
🏆 消灭了 -0，把腾出来的位置送给了 -128。现代计算机的整数，全是它。
Offset / Excess-N

移码 补码戴了个反面具

把补码的符号位取反就是移码；等价于真值 + 2ⁿ⁻¹。

-9 → 01110111  （-9 + 128 = 119）
🎯 整数整体搬到非负区间后，用无符号比较器就能直接比大小——所以浮点数的阶码爱死它了（IEEE754 单精度偏移 127）。

03取值范围：谁比谁多一个数

核心记忆口诀：原码反码少两个（±0 占了两份），补码移码多一个（那个"多出来的最小负数"）。小数点位置不同，公式要换一套，别背串。

04转换逻辑：一条链条串起来

正数四种码长得一模一样（只有符号位是 0）；负数才需要变戏法。

真值 x

反码 +1 / 符号位取反
正数（x ≥ 0）：原码 = 反码 = 补码 = 0xxxxxxx，移码 = 1xxxxxxx（符号位取反）。
负数（x < 0）：原码 → 符号位不变、数值位按位取反 → 反码 → 末位 +1 → 补码 → 符号位取反 → 移码。
逆运算：补码 → 原码，对补码再做一次「取反+1」即可（自己就是自己的补，妙不妙）；移码 → 补码，符号位取反即可。
⚡ 快速技巧（软考提速）：已知 [X]补 求 [−X]补 —— 从右往左找到第一个 1，这个 1 及其右边原样保留，左边（含符号位）全部取反。
